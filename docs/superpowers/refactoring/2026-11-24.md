# refactoring-2026-11-24

根据目前读取到的 `qiaomu-blog-opensource` 分支源码，建议按优先级处理：**先拆分编辑器和通用组件，不重做文章管理、认证权限、AI、主题及搜索，也不引入复杂的图片管理系统。**

先说两个关键判断：

1. Markdown 编辑器已经不是简单的文本编辑框，而是一套基于 Novel / Tiptap 的富文本编辑系统，功能比较丰富。
2. `NovelEditor.tsx` 有 **2774 行**，`editor-extensions.tsx` 有 **1393 行**。这两个文件是第一批值得拆分的对象，但不应该为了拆分而改变编辑器现有行为。

### **我认为最需要关注的是 Markdown 处理链**

目前能确认项目存在几种不同的处理方式：

**Markdown → HTML**

`markdown-it`

**HTML → Markdown**

`turndown`

**Markdown ↔ Tiptap**

`tiptap-markdown`

**Frontmatter**

`gray-matter`

这几个库的职责并不完全相同，不建议强行只保留一个。

但是需要统一入口，避免不同页面各自实现一套 Markdown 转换逻辑。

建议将 Markdown 处理集中在：

```
lib/markdown/
├── parser.ts
├── renderer.ts
├── serializer.ts
├── frontmatter.ts
├── math.ts
└── index.ts
```

并且要明确：

- 编辑器内部使用什么格式保存内容。
- 数据库存储 HTML、Markdown 还是两者。
- 导入 Markdown 后如何转换为 Tiptap Document。
- 导出 Markdown 时如何处理自定义节点。
- 文章预览和 AI 对话是否使用相同的渲染规则。

尤其要注意自定义 WeChat 节点、数学公式、视频等内容的 Markdown 往返转换。不能只测试普通段落，否则很容易发生内容丢失。

另外，当前 `editor-extensions.tsx` 中配置了 `Markdown.configure({ html: true })`，而 Markdown 渲染器配置了 `html: false`。建议明确 HTML 的允许范围，并审查导入、粘贴及 `dangerouslySetInnerHTML` 的内容净化策略。这是安全性和内容一致性问题，不只是代码整理。

## **6. 推荐重构顺序**

我建议按照下面顺序执行，避免一次性大规模修改导致编辑器功能回归。

1. **第一阶段：整理编辑器核心**
   - 拆分 `NovelEditor.tsx`
   - 拆分自动保存逻辑
   - 拆分编辑器 UI、侧边栏、目录
   - 保持现有功能和视觉效果不变
2. **第二阶段：整理 Tiptap 扩展**
   - 拆分 `editor-extensions.tsx`
   - 分类管理基础扩展、媒体扩展、自定义节点
   - 拆分 Slash Menu 和 Bubble Menu
   - 保留现有扩展注册顺序，验证节点兼容性
3. **第三阶段：统一 Markdown 处理**
   - 统一 Markdown 转换入口
   - 统一导入、导出、预览处理
   - 验证公式、表格、图片、自定义节点的转换
   - 清理未使用的 Markdown 依赖
4. **第四阶段：接入 PicX**
   - 增加 PicX 上传适配器
   - 增加轻量上传代理 API
   - 替换编辑器原来的图片上传请求
   - 保留上传进度、压缩、错误反馈
5. **第五阶段：通用组件整理**
   - 识别重复 UI
   - 提取通用 Modal、Dropdown、Toolbar 等
   - 清理重复代码和无用依赖
   - 补充必要的测试

每个阶段都应单独运行测试、类型检查和构建，确认功能一致后再进入下一阶段。

## **7. 最终建议**

我认为目前不需要更换编辑器，也不需要引入大型上传管理库。真正值得做的是：

| 优先级 | 工作                               | 处理方式      |
| ------ | ---------------------------------- | ------------- |
| P0     | `NovelEditor.tsx`                  | 拆分          |
| P0     | `editor-extensions.tsx`            | 拆分          |
| P1     | Markdown 处理链                    | 统一入口      |
| P1     | 自定义 Tiptap 节点                 | 分类整理      |
| P2     | 通用 UI                            | 提取复用      |
| 暂缓   | 文章管理、认证权限、AI、主题、搜索 | 保持不动      |

**还有一个重要建议：不要把“拆分文件”变成“重写功能”。** 这次应该以保持现有功能、数据结构、编辑体验和页面设计为前提，只调整模块边界和依赖关系。
